策略卡 v2：什么时候加仓、什么时候平稳、什么时候加速——按所有起点搜出来的规则

写于 2026-08-17。搜索代码 backtest/optimize.js（543 条规则）+ backtest/optimize2.js（再平衡 / 抄底规则）；结果 backtest/strategy_results*.json。可自动执行的版本：strategy/agent.py + strategy/rules.json（§4）。

0. 结论

「无论何时入场都最优」的规则不是一条择时规则，而是一套「尽快进场 + 固定定投 + 宽带宽机械再平衡」的纪律。 我把规则族参数化（入场节奏 × 回撤触发器 × 均线调速 × 机会储备金 × 再平衡方式），在真实 2004–2026 的每一个起点、再加 1,100 条自助抽样出的替代历史上跑，用风险厌恶效用（CRRA，γ=3；也看了 γ=1 和 5）打分。结果非常一致：

规则族里的旋钮对效用的影响（相对一次性 = 1.0000）判断
入场节奏 NN=3：0.9927 · N=6：0.9902 · N=12：0.9863 · N=24：0.9794（各参数下平均）越快越好；每多等 6 个月约付 0.3–0.4%
回撤触发器（10/20/30 等 5 种）0.9865–0.9867，与「无」无差别对期望中性，只在行为上有价值
均线调速：均线下 ×2+0.0004（唯一为正的调速）微弱正向，可用
均线调速：新高时减速 ×0.5−0.0007 ~ −0.0011负向，不做
机会储备金 5% / 10%−0.5% / −1.0%负向，不做
再平衡：10% 带宽（每月查）vs 每年一次+0.3%正向，采用
再平衡：回撤 ≥15% 时股票 +10pp 倾斜真实样本中位 +2%，但自助样本 CE −0.2%、P10 更低不稳健，不做
再平衡：回撤 ≥30% 时股票 +15pp真实 CE +0.5%，自助 CE −1.2%不稳健，不做

于是「最优解」长这样（§1）。它和 entry-plan.md 的差别只有两处：股票层入场从 12 个月缩到 6 个月（省 0.5% 效用），再平衡从「每年一次」改成 「每月查、偏离 >10 个百分点才动」（+0.3%）。触发器保留但不指望它赚钱。

一句大白话：加仓的时机由「权重偏离」决定，不由「感觉便宜」决定；平稳是默认状态；加速只发生在入场期。

读法：

  • 从上到下就是「舒适度的价签」：一次性 → 3 个月 → 6 个月 → 12 个月，每一档约 0.2–0.5% 的效用，换的是「头两年最低点」从 505k → 511k → 518k → 535k。策略卡选 6 个月：付 0.2–0.5%，买到 +13k 的最坏情况保护 + 一个可执行的入场流程。心理上需要 12 个月的人，价签是再 0.5%。
  • 10% 带宽再平衡在每一行都加 0.3%（对比同节奏的年度再平衡）：它在股票相对跌 25–30% 时会自动从债 / 现金里买回股票，在涨多了时自动卖——这就是「什么时候加仓」的数学答案，而且不需要预测。
  • 「回撤倾斜加仓」（跌了不只买回目标、还额外超配）在真实样本里赚了（因为 2009、2020 都是 V 形），在随机化起点的自助样本里亏了——典型的过拟合信号，所以不进策略卡。

2.3 触发器到底有没有用

543 条规则里，5 种触发器参数的平均分 0.9865–0.9867，「无触发器」0.9867。触发器动过的起点里胜负大约 55:45，中位差 +1–2k。它不是收益工具，是行为工具：跌的时候手里有一条写死的规则，比「再看看」强。保留。

2.4 为什么「尽快进场」在效用上赢，但策略卡还是留了 6 个月

CE 打分只看 10 年后的财富分布，看不见「第 3 个月账户 −12% 时的那个晚上」。60/40 组合本身已经把回撤压到 −9%（中位）/ −24%（最差），所以在数学上多等是净成本；6 个月是我在数学（0.2–0.5%）和执行现实（一对第一次投 60 万的夫妇）之间选的点。这个选择在 strategy/rules.json 里是一个数字，随时可以改成 3 或 12。

3. 局限（照旧诚实）

  • 规则族是我定义的；没有搜过「按估值（CAPE）调速」「按波动率调仓」等，那些在文献里对个人投资者也基本是中性的，但没在这里验证。
  • 自助抽样打乱了跨年份的长周期结构（比如 2008 后 13 年的长牛），保留了年内结构。压低均值的集是对「未来更差」的粗糙检验，不是预测。
  • 效用函数是 CRRA 终值；没有对路径痛苦（回撤持续时间）建模。
  • 新加坡短期利率近似年表、REIT 并入新加坡股、汇率起点 2003-12——与 backtest.md 相同。

4. 写成代码、自动运行

4.1 文件

文件作用
strategy/rules.json策略卡的全部参数（金额、比例、工具代码、入场月数、触发器、均线、带宽）
strategy/state.json状态：起投月、持仓（份数 / 现金金额）、未进场现金、入场进度、已记账月份、历史
strategy/agent.py每月跑一次：拉最新价（Yahoo：VWRA.L / ES3.SI / CLR.SI / AGGU.L / IGLN.L / SGD=X），算信号（VWRA 新元价、10 月均线、自起投最高点回撤），按策略卡生成本月动作清单（入场买入 / 定投 / 再平衡买卖，金额 + 约合份数），写 strategy/log/YYYY-MM.md

4.2 用法

python3 strategy/agent.py --init 2026-09        # 起投月（资金到账的下一个月）
python3 strategy/agent.py                        # 每月：看这个月该做什么（不改状态）
python3 strategy/agent.py --apply                # 在券商执行完之后：按建议价记账
python3 strategy/agent.py --set gEq=180.03 sgEq=1725 cash=30000   # 用真实持仓（份数 / 新元）覆盖记账
  • 同一个月重复运行只更新那份日志；--apply 同月只记一次。
  • 现金类（SSB / T-bill / 高息户）按新元金额记，不拉价。
  • 已用 2026-08 的真实行情干跑过：信号 VWRA 新元 249.96、10 月均线 229.91（之上）、回撤 0% → 第 1 个月动作 = 安全层 21 万 + 黄金 5k + 股票层 6 万（45k VWRA / 10k ES3 / 5k CLR）+ 定投 6,600，合计 S$281,600。再平衡分支用伪造的失衡持仓测过（股票权重低 → 买股票卖债）。

4.4 想改规则

改 strategy/rules.json 即可；要重新验证某个改动是否更好，把参数填进 backtest/optimize2.js 的 ENTRIES / REBALS 跑一遍（node backtest/optimize2.js，约 30 秒），看 CE 相对一次性的分数——只有在真实和自助两个集上都 ≥ 现有规则才采用。这就是「策略升级」的流程，也写死了。
